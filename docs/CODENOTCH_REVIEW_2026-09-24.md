# CodeNotch 参考评审与 Usage Tracking 改进建议

Author: Zeno Ren

评审日期：2026-09-24。当前项目：v0.4.5，`2cecf40`。参考项目：`vinzdg/codenotch`，本次查询 HEAD 为 `731a23d8e057862c2ff151bde8e8d9274f5e950a`。

## 结论

值得改进。优先借鉴 CodeNotch 的信息层级：品牌识别、额度压力、重置时间、按需展开；保留 Usage Tracking 的本地历史、项目和成本分析优势。先完善已有菜单面板，再考虑可选的贴边悬浮模式。

本次是评审与交互示意，没有修改 Swift 实现、连接配置、账户登录或安装版本。示意中的用量、额度、项目和时间均为虚构数据。设计示意采用通用图标，原生实现应继续使用现有且带归属声明的品牌素材。

## 参考图好在哪里

官方图的三枚圆环每枚只承担一个主信息：已用比例。品牌标志居中，数字独立，彩色只占很小面积。鼠标停留后，独立卡片再展示不同额度窗口和重置时间。黑色贴边外形进一步减少了面板边框和导航的存在感。

可迁移的部分：

- 放大关键读数的视觉占比，把品牌颜色与额度风险分开表达。
- 让重置时间和快照新鲜度容易发现。
- 将完整窗口、绝对计数、来源、错误和恢复入口放入可停留、可点击、可键盘访问的详情。
- 空闲时安静，仅在额度或任务状态确实值得关注时提醒。

适配时需要保留的边界：

- 官方早期设计稿写“最高窗口”，但当前 README 特别说明 Claude 主环跟随其 current-session 窗口；不能把早期文档当成最新全部行为。我们已有“有效窗口中最高比例”的实现和测试，建议先保留并明示窗口名称。
- 该项目所谓官方来源包含内部接口、工具 RPC、本地缓存等，并不等于供应商承诺稳定的公开 API。
- 贴边 NSPanel 带来多显示器、全屏、Spaces、缩放和焦点管理成本；只适合作为后续可选入口。
- 任务完成/等待输入需要明确生命周期信号，不能把文件最近写入或 Token 增长直接解释为“正在工作”。

## UI/UX 优先级

| 优先级 | 当前证据 | 建议 | 用户收益 |
| --- | --- | --- | --- |
| P1 | `MenuQuotaCard.swift:61–67` 圆环只有 18pt，品牌标志另占一行；颜色主要按工具固定 | 采用约 40–48pt 的额度环并将品牌放在中间；数字保留；中性色表面，风险色只用于进度和状态 | 更快判断哪个工具接近上限 |
| P1 | `MenuQuotaCard.swift:24` 副标题 9pt；重置时间只在 `MenuQuotaSummary.details` 和账户页 | 在主卡显示窗口名和简短倒计时；缺失时间写“未提供”，已过时间写“等待新窗口” | 不必悬停猜测何时恢复 |
| P1 | 当前卡片详情依赖 `.help`，刷新按钮 18×18pt | 点击卡片打开锚定详情；保留独立刷新；键盘可到达、Esc 关闭，错误说明旁放恢复动作 | 详情可停留阅读，异常可处理 |
| P1 | 未获取额度、旧快照、刷新失败已有底层区分，但主卡只用 `—` 或小图标 | 明示“未连接 / 等待首次数据 / 旧快照 / 刷新失败”；保留旧值且标时间，状态不限于颜色 | 用户知道数值可信度与下一步 |
| P1 | `MenuUsageOverview.swift:45` 和 `MenuTopProjects` 的数字点击会切换整块单位 | 用明确的 `Token / 参考 USD` 分段控件；数字用于详情，项目行用于项目下钻 | 操作结果更可预测 |
| P2 | 主窗口侧栏 9 个同级入口，部分页开头是较长解释文案 | 分为“总览 / 分析 / 管理”；成本与模型价格保持可互达；方法说明折叠，缺失和异常仍紧贴数值 | 降低首次使用时的阅读负担 |
| P2 | 项目、会话用卡片列表；趋势图无日期选择明细 | 大数据页增加原生表格排序和明确筛选摘要；图表选择某日显示工具明细；日期近似提示随数据出现 | 支持比较、定位和核对 |
| P2 | 总览对无记录工具显示数值 0 并附“暂无用量”，菜单则显示 `—` | 统一未知与真实零值的展示规则；总览价格覆盖不足时直接标“部分定价” | 菜单和工作台语义一致 |
| P2 | 主窗口全局导出按钮也出现在账户、价格、设置页；`AppModel.export` 除客户端页外导出本地筛选事件 | 只在对应分析页显示导出，或明确“导出本地用量”；导出前说明时间、工具和记录范围 | 避免把账户页导出误认成额度导出 |

额度压力配色建议：低于 80% 常规色、80–89% 提醒色、90% 及以上警示色，同时显示文字。最终阈值应与产品通知设置保持一致；品牌由标志识别。无数据时不绘制伪造进度；旧快照弱化进度并明确标注。窗口不相加，Copilot Credits / Requests 保留服务返回单位。

菜单仍应保留今天、7 天、30 天用量和今日 Top 3。默认折叠详情；示意采用面板内展开方便对比，原生实现宜使用锚定详情以控制主面板高度。保留“打开工作台”、暂停及手动刷新路径。

## 其他值得改进的地方

### 1. 额度缓存需要账户身份边界（P1，代码风险）

`CodexQuota.swift:64` 的 ID 是 `rpc:<limit>:<window>`；`CopilotQuota.swift:53` 是 `copilot-rpc:<window>`。`QuotaWindow` 无账户标识，`Database.swift:83–91` 按工具前缀替换快照，失败时 UI 保留旧值。

因此切换工具登录账户后，若首次新查询失败，旧读数没有账户归属信息供 UI 核对。当前并未现场复现串号；这是数据模型缺口，README 也已声明正式多账号隔离未完成。建议只通过工具可用的只读接口取得不含凭据的账户/配置作用域，纳入缓存键；无法验证归属时标“账户待确认”，不要称为当前账户新鲜读数。无需为此读取凭据。

### 2. 通知去重应跨重启（P1，代码路径确认）

`AppModel.swift:51` 的 `notified` 只存在内存，`checkNotifications()` 在新鲜窗口达到 90% 时立即提交通知。重启后集合为空，同一高额度窗口可以重新进入提交路径。目前没有跨进程的去重状态或真正的阈值跨越状态。

建议持久化“账户 / 窗口 / 重置标识 / 阈值”的提醒状态；同窗口刷新和重启不重复提醒，确认新窗口后重新允许。通知投递失败不应提前永久标记成功。是否加 80% / 100% 档位属于产品选择，不是修复前提。新增测试覆盖重启、重复刷新、窗口重置、旧快照及投递失败。

### 3. 刷新退避可以持久化（P2，代码路径确认）

现有刷新调度已防重叠、失败退避、唤醒不追赶，基础合理。`RefreshSchedule` 的完成时间与失败次数只保存在内存，应用重启会恢复立即查询。可参考 CodeNotch 保存限流截止时间的做法；服务提供 Retry-After 时保留最早允许重试时间，避免通过重启绕开退避。

### 4. 聚合与扫描需要基准后再优化（P2，待测量）

菜单摘要已经在后台计算。工作台的 `filtered / projects / sessions / daily / costCoverage` 仍是 `@MainActor AppModel` 的即时计算属性；一次重绘可重复过滤、分组和定价。扫描虽然有增量游标，仍会枚举来源目录，并在 `cached()` 载入完整历史。

建议用脱敏或合成的 1 万 / 10 万条数据测量首次打开、切换时间、搜索延迟、扫描 CPU、内存峰值，再决定缓存查询快照、SQL 聚合、搜索去抖或文件变化驱动。不能仅凭代码宣称当前已卡顿或耗电。

### 5. 分发与可维护性（P2）

- 仓库工作区留存的界面图片是 v0.2 的本地旧截图，且它包含私人用量并被 `.gitignore` 排除。当前 README 缺少新版产品图；应为 v0.4.5 以后准备固定样例数据的截图，不将本机真实项目/用量用于公开展示。
- 已有 CI 构建和测试；本次编译出现 `AppModel.swift:95` 内外层 self 捕获所有权不一致警告，可单独小改整理，不混入视觉重构。
- 公开发布仍是 ad-hoc 签名；Developer ID 签名、公证及可验证更新会改善首次安装体验。需要相应签名资源，属于独立发行工作。
- 新增工具前逐步提取 Provider 协议，明确额度能力、刷新方式、覆盖率、账户作用域和失败状态。当前三工具不值得为抽象本身整体重写。

## 推荐交付顺序与验收

1. 第一批：额度卡片、重置时间、详情展开、明确的单位切换、项目下钻。保持统计和计价规则；先补窗口/时间/状态行为测试，再调整界面。
2. 第二批：账户缓存作用域、通知去重、导出语义、工作台导航和数据页。
3. 第三批：根据实际需求增加可选贴边模式、任务生命周期提醒与更多工具。

第一批验收：

- 验证 0%、无数据、部分旧窗口、全部旧窗口、100% 以上、缺失/过期重置时刻、Credits/Requests、部分定价。
- 深浅色、常见 macOS 桌面尺寸、长窗口名、键盘焦点、VoiceOver、减少动态效果；重要含义不只靠颜色。
- Token 与参考成本切换不改变 Top 3 的 Token 排名；项目点击保持正确项目/时间范围。
- `swift test`、`Scripts/build-app.sh`、实际 App 启动与主界面交互验证。
